How RapReaper uses it
------------------
* bridge/reaper_agent_bridge.lua runs inside REAPER and carries out commands it finds as
  small JSON files in kit/reaper-daemon/inbox. The bridge can do more than RapReaper lets
  through (for example delete a track or save the project). RapReaper's server only ever
  sends the commands on its own short allow-list (see READ_COMMANDS and WRITE_COMMANDS
  near the top of kit/rapreaper_server.py), and the bridge's own switches for "save the
  project" stay OFF in kit/reaper-daemon/bridge/bridge_config.json.
* reaperd.py is imported for four functions only: send_command (write a command file),
  _queue_file (where that command's reply file will appear; RapReaper reads the reply
  itself), resolve_fx_name (look a plug-in name up in REAPER's plug-in list) and
  find_resource_dir (where that list lives). The rest of that file belongs to features
  RapReaper does not use.
* setup/install.py supplies the text of the bridge's auto-start block (block_text) and the
  helpers for the bridge's permission file (read_config, set_gates). rapreaper_install.py
  writes that block into REAPER's Scripts/__startup.lua itself, so that a startup script
  with unusual encoding keeps every byte of your own lines. Above it, it writes a second
  short block of RapReaper's own: at every start of REAPER it notes the time in
  kit/state/reaper_started.txt (that is how RapReaper tells a REAPER that crashed in the
  middle of a measurement, and was started again, from one that is merely busy) and then
  starts kit/rapreaper_helper.lua, RapReaper's own helper. The bridge cannot split a clip or
  read a plug-in's settings block; the helper does only that (see the notes at its top),
  through its own small JSON files in kit/state/helper, and is RapReaper's own code.

Before shipping, the upstream project's own tests were run on these exact files
(bridge/test_bridge.lua: 624 checks passed; bridge/test_json.lua: 40 passed), and both
this component and RapReaper were read for network access and hidden behaviour: none found.

Plug-ins RapReaper adds in REAPER
------------------------------
All of them ship with REAPER itself: ReaEQ, ReaComp, ReaLimit, ReaVerbate, ReaDelay
(Cockos) and the JS effects "RBJ Highpass/Lowpass Filters" and "Downward Expander"
(Stillwell), "De-esser" (Liteon), "Volume/Pan Smoother" and "Tone Generator" (Cockos),
"Master Limiter" (Loser). Nothing extra is downloaded.

NumPy and SciPy (BSD licences), installed by pip from https://pypi.org .

ffmpeg (https://ffmpeg.org, LGPL/GPL) for MP3 and M4A copies of exports; whisper.cpp
(https://github.com/ggerganov/whisper.cpp, MIT licence) with an OpenAI Whisper model file

Reference data
--------------
The "natural speech" tone yardstick in kit/rapreaper_audio.py is derived from Table II of
Byrne et al., "An international comparison of long-term average speech spectra",
J. Acoust. Soc. Am. 96(4), 2108-2120 (1994). Loudness is measured as defined in
ITU-R BS.1770 and EBU R 128 / Tech 3341 / Tech 3342.

Vocal separation (separate_song, learn_song_effects) and the Vocal Remover 2.0
----------------------------------------------------------------------------
kit/rapreaper_separate.py takes the voice out of a song with the Vocal Remover's networks: either by
starting the Vocal Remover program shipped in VocalRemover/ (allowed by the installer by path and
SHA-256; its own source is in VocalRemover/source and its own notices in VocalRemover/licenses), or
by running the same model file through Microsoft's ONNX Runtime (MIT licence), installed as the Python
package "onnxruntime" by the installer. The models, from the Ultimate Vocal Remover community
(Anjok07 and aufr33, MIT licence; https://github.com/Anjok07/ultimatevocalremovergui), are NOT in the
zip or the GitHub repository: they are large, and their authors published no licence that lets anyone
else pass the files on (Kimberley Jensen's base model is MIT; unwa's fine-tune, viperx's BS-Roformer and
the MDX files state none). So each person gets them from the authors: "Get Vocal Remover Model" downloads
unwa's two public files (checked) and the installer builds MelRoformer-KimFT2-int8.onnx from them; or
pieces delivered with RapReaper are joined. The installer checks every model file:

        https://huggingface.co/KimberleyJSN/melbandroformer), fine-tuned by unwa
        (https://huggingface.co/pcunwa/Kim-Mel-Band-Roformer-FT, kimmel_unwa_ft2.ckpt); the ONNX
        file is built from the public checkpoint by VocalRemover/source/tools/build_roformer_onnx.py

    a31b1fed94ed5fcf3c8ef41f9cf55a31ba6da2f1028d91d296907ced99b23cdf   BS-Roformer-1297-int8.onnx
        "BS-Roformer-Viperx-1297" by viperx (checkpoint model_bs_roformer_ep_317_sdr_12.9755), built
        the same way
    ce74ef3b6a6024ce44211a07be9cf8bc6d87728cc852a68ab34eb8e58cde9c8b   Kim_Vocal_2.onnx

The Band-Split and Mel-Band RoPE Transformer architectures are by Lu, Wang et al. (ByteDance, 2023;
arXiv 2309.02612 and 2310.01809); the open implementations by Phil Wang (lucidrains/BS-RoFormer, MIT)
and Roman Solovyev (ZFTurbo/Music-Source-Separation-Training, MIT). The processing around the MDX
network (FFT size 7680, hop 1024, 3072 bins, 256 frames, gain correction 1.009) comes from the UVR
model database (https://github.com/TRvlvr/application_data); the Roformer windows (8 s, hop 441,
one-second crossfades) follow the reference inference. The UVR project asks programs that use its
models to credit UVR and its developers; RapReaper does so gladly. Quality was measured on test songs
of MUSDB18-HQ (Rafii et al., 2019) against their true stems; the numbers are in the guides.

arm64, and 1.23.2 for macOS x86_64 in the Intel Mac package (SHA-256 of libonnxruntime.1.23.2.dylib:
8c9c78de65ea3786f987c0d980e9c1b13a3a5fbc6b3e2965ba05b450e6e4c054) (MIT; unchanged official files from
github.com/microsoft/onnxruntime/releases), ONNX Runtime
1.24.4 built with DirectML and DirectML 1.15.4 (Microsoft; NuGet packages Microsoft.ML.OnnxRuntime

on), the Microsoft Visual C++ runtime 14.40 (Windows), purego (Apache 2.0), go-mp3 (Apache 2.0,
modified: see VocalRemover/source/internal/mp3/MODIFICATIONS.md), mewkiz/flac (public domain) with
icza/bitio (Apache 2.0), and jfreymuth/oggvorbis and vorbis (MIT). Every checksum is in

The key detector in kit/rapreaper_effects.py uses the key profiles of Krumhansl & Kessler (1982),
Psychological Review 89(4), 334-368.

Tempo, key and alignment (kit/rapreaper_music.py, 1.4.0)
---------------------------------------------------------
The tempo finder follows the usual onset-strength autocorrelation of Ellis, "Beat tracking by dynamic
programming", J. New Music Research 36(1), 51-60 (2007), with a mild preference for the tempos drum
machines are set to; the key finder of a beat uses the same Krumhansl & Kessler (1982) profiles as the
one for a sung line; lining two recordings up is plain normalized cross-correlation of their attack
curves and then of their waveforms. The reference cards' loudness figures are those published by the
streaming services (Spotify's loudness-normalization page and the others' published figures, October
2026); everything else in the cards is common mixing practice written down, not taken from any one source.
