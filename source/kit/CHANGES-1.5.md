# RapReaper 1.5: any AI app, and an AI of its own

## 1.5.0, nightly: any AI app that speaks MCP, and RapReaper's Local AI (12 November 2026)

A nightly build on the GitHub branch "Nightly". Before 1.5.0 RapReaper was written for one AI app, Claude Desktop:
the installer connected only that app, and the tool server assumed it in its words, its timing notes and its privacy
notes. RapReaper has always been an MCP server, the standard way AI apps use tools, so any app that speaks MCP could
drive it; 1.5.0 makes that real, and adds an AI that runs on the person's own computer.

| Problem met | Change |
|---|---|
| The installer added RapReaper only to Claude Desktop's settings, and without Claude Desktop it never said ALL SET ("Claude Desktop does not seem to be installed"). | Step 5 is "AI apps": RapReaper is added to every AI app found (`PF.ai_apps()`): Claude Desktop (as before), ChatGPT's desktop app and Codex (`~/.codex/config.toml`, `[mcp_servers.rapreaper]` with `startup_timeout_sec` 60 and `tool_timeout_sec` 120), Cursor (`~/.cursor/mcp.json`), VS Code and VS Code Insiders (the user `mcp.json`, `servers` with `"type": "stdio"`), Windsurf (`~/.codeium/windsurf/mcp_config.json`), LM Studio (`~/.lmstudio/mcp.json`) and Gemini CLI (`~/.gemini/settings.json`). Each file is backed up first. A JSON file with comments is left as it is (a note, not a TO DO). config.toml is edited as text and read back with `tomllib`: unless everything else reads exactly as before, nothing is written. `kit/state/ai_app_settings.txt` has the settings for any other app (the three values, mcpServers / VS Code / Codex / Zed blocks, the Claude Code command). `--ai-apps all|none|claude,chatgpt,...` chooses (remembered in install.json); Uninstall takes the entry out of every app. With no app at all, the TO DO offers RapReaper's Local AI first. Scenario `ai_apps`. |
| The tool server's answers assumed Claude: "while Claude is in front", "Claude waits only about a minute", "Quit Claude completely and open it again", "everything in this chat goes to Anthropic", `sent_to_claude.log`, `restart_claude`. Wrong, and for privacy misleading, in any other app. | The server reads the app's name from the MCP handshake (`clientInfo`; from each request's `_meta` in the 2026-07-28 protocol) and `PF.wording` puts it where the texts say "your AI app". The privacy notes (instructions, privacy tool) say who reads the chat: Anthropic for Claude, OpenAI for ChatGPT and Codex, Google for Gemini, "whoever runs the model chosen in Cursor" for apps where the person picks the model, "this computer" for LM Studio and the Local AI. The restart advice follows the app (a terminal app: a new session). The activity log is `kit/logs/sent_to_ai.log` (headed "SENT TO CURSOR", say); 1.4's `sent_to_claude*.log` files are still counted, swept and cleared. `restart_claude` is `restart_ai_app`. The playbook names no app. |
| Some apps refuse or mangle tool schemas that Claude takes: a list of types (`["string", "number"]`: Gemini and some editors), an object without properties (sent as text by some apps), `additionalProperties: false` (refused by some Gemini paths). A few apps use only the first 40 or so tools of a server, and a small model has no room for 57 tool descriptions. | Published schemas take the portable form (`_portable`): the first type where RapReaper takes several, free-form objects marked `additionalProperties: true`, no `additionalProperties: false`. RapReaper's own check keeps the full schema, so everything accepted before still is; an object sent as JSON text is now read as the object. The 28 core tools (`CORE_TOOLS`) come first in every list; `RAPREAPER_TOOLS=core` lists only those, and `playbook` then gives `PLAYBOOK-CORE.md`, a short form that names no other tool. status says which app and which tool set. |
| The person asked for an AI that comes with RapReaper and runs on their own computer, without an account or subscription. | RapReaper's Local AI. `Get Local AI.bat` / `.command` downloads, once, llama.cpp's llama-server (build b12250, MIT; the Vulkan build on Windows, which falls back to the processor; the Apple-chip or Intel build on a Mac) and Qwen 3.5 (Apache 2.0; 4B, 2.7 GB, or 9B, 5.7 GB, chosen by the computer's memory), each checked against the SHA-256 in the script, from a pinned release and a pinned model revision. `Start Local AI.bat` / `.command` (`rapreaper_install.py --local-ai`) checks every runtime file against `LocalAI/runtime-b12250.json` and refuses any other file there (llama.cpp loads the libraries next to it; only the .DS_Store, Thumbs.db and desktop.ini that Finder and Explorer leave in an opened folder are let through), checks the model's checksum once per size and date, writes `kit/state/local_ai/mcp.json` (RapReaper with `RAPREAPER_TOOLS=core`, `RAPREAPER_AI_APP=local`, two minutes per call) and `ui.json` (the chat window's system message), checks that RapReaper's tool server lists its tools when started from that file the way llama.cpp starts it (llama.cpp's own start-up waits only 10 seconds for them, then carries on without them), and starts llama-server on 127.0.0.1 (port 8077, or the next free one; 32k context, one slot, thinking off unless `--think`), retrying once on the processor only (`--device none`) when it stops while starting on the graphics processor, and starting it once more when its start-up got none of RapReaper's tools (a second time, it is stopped with a note, as a chat without the tools could not change anything); then opens the browser. llama-server's own guards refuse other web pages and computers, and its chat window asks before every tool call. The installer counts the Local AI as an AI app. Scenario `local_ai` (with a stand-in llama-server). |

Versions: server, installer and helper 1.5.0 (the helper's only change is its version line). The Vocal Remover is
unchanged (2.0.3). New files: `kit/PLAYBOOK-CORE.md`, `kit/CHANGES-1.5.md`, `Get Local AI.bat`, `get_local_ai.ps1`,
`Start Local AI.bat`, `Get Local AI.command`, `Start Local AI.command`, `LocalAI/README.txt`, `LocalAI/licenses/`,
`LocalAI/runtime-b12250.json`, and the empty `LocalAI/runtime` and `LocalAI/models` (kept by the updater).

Run in the build environment (Linux, 2 processor cores, about 6 GB of memory for programs): the real llama-server b12250 with the real Qwen 3.5 4B
file, RapReaper as its MCP server exactly as Start Local AI configures it, against the simulated REAPER, driven the
way llama.cpp's chat window drives it. Its start-up listed all 28 tools; the model called status, the playbook and
the self-test (27 of 27 passed) and reported them truthfully; asked for a vocal chain it ran plan, cleanup, compress,
tone, de-ess and finish on its own, and after a yes balanced the vocal against the beat, with summaries that match the
tools' numbers. On those 2 cores an answer took one to seven minutes. One problem found: llama.cpp keeps earlier
conversations' state in memory, up to 8 GB by default, and ran out of memory there (the model itself takes about 4 GB
with a 32k context); Start Local AI now passes `--cache-ram 1024`, and the same conversation then ran to the end
(5.6 GB at most, including the model file's pages). The Windows and Mac builds of llama.cpp were not run (no such
computer); the launcher's handling of them was tested with a stand-in llama-server.
